# 自动翻页 · 可视化规则

将下一页的列表条目追加到当前页面，为多个网站分别保存可视化适配规则。当前版本为 **1.8.2**。

## 安装与更新

**[安装或更新脚本](https://raw.githubusercontent.com/1789984734/visual-autopager/main/visual-autopager.user.js)**

在安装了 Tampermonkey 的 Chrome 上打开这个链接，按提示安装。已安装旧版本时，选择更新现有脚本。

如果浏览器只显示源码，可以打开 **Tampermonkey 管理面板 → 实用工具 → 从 URL 导入**，填入上述链接进行安装，无需复制整段代码。

安装后，在脚本的设置中开启更新检查；支持“自动安装更新 / Automatic installation”的版本也需开启该选项。以后会从固定地址获取新版。需要立即更新时，在脚本菜单或管理面板使用“检查更新”，完成后刷新目标网页。

- 安装与完整下载地址：`https://raw.githubusercontent.com/1789984734/visual-autopager/main/visual-autopager.user.js`
- 版本检查地址：`https://raw.githubusercontent.com/1789984734/visual-autopager/main/visual-autopager.meta.js`

脚本名称、命名空间和规则存储键在升级时保持一致。更新现有安装即可继续使用原来的配置；如果要备份规则，使用脚本配置面板中的 JSON 导出功能。

## 配置一个网站

1. 点击浏览器工具栏上的篡改猴图标，选择 **自动翻页：配置当前网站**。
2. 点选包含列表的内容容器；选错层级时，可通过“选择父级 ↑”调整。
3. 点选一个完整条目，例如卡片、帖子或表格行。
4. 点选带真实 `href` 的下一页链接。
5. 使用“高亮检查”和“检查下一页”确认范围，然后保存规则。

点选时会阻止链接跳转。点击锁定候选元素，Enter 确认，Esc 取消。选择器也可以手动修改。

匹配路径忽略查询参数。例如 `/?page=1` 的匹配路径填写 `/`；`/forum/*` 可以覆盖多个论坛列表路径。

## 日常使用

网页上没有常驻按钮或面板。通过篡改猴菜单可以配置规则、暂停或继续、手动加载下一页，以及重试失败请求。

默认提前 800px 加载下一页，最多显示 30 页（含当前页），可在规则中调整。每次只请求一页，支持去重、分页循环检测、末页停止和失败重试。

“条目链接在后台新标签页打开”是每条规则的独立开关，默认关闭。开启后，普通单击当前页或追加条目的 HTTP / HTTPS 链接，会在后台新标签页打开点击时的 `href`，继续停留在列表页。原先已经勾选“条目链接在新标签页打开”的规则，更新后直接使用后台打开，无需重新配置。关闭开关时恢复原始链接属性并移除点击监听。

使用 [Tampermonkey 的 GM_openInTab](https://www.tampermonkey.net/documentation.php?locale=zh_&q=GM_openInTab) 的 `active: false` 选项。v1.5.2 新增对应的 `@grant`；更新后刷新网页生效。锚点、下载、分页、组合键点击及中键仍交由网页和浏览器处理。点选配置期间不会打开详情。

配置时会暂停自动加载；需要继续时使用菜单“自动翻页：暂停 / 继续”。

v1.5.4 修复追加页面中 `magnet:` 磁力链接被清空的问题：允许条目链接保留 `magnet:` 协议，解决资源分享站（如 u3c3 等）翻页后磁力链接图标变为空链接的问题。保持原生点击行为，不被后台打开机制拦截。

v1.5.3 修复一种“追加第二页后误报最后一页”的情况：部分页面用 Bootstrap Paginator 动态创建分页按钮，抓取的 HTML 中只有分页参数。对已识别的 `p / type / search2 / search` 地址格式，脚本会读取当前页、总页数和字面量参数，生成后续同源地址，并使用每页更新的搜索参数。只处理与规则选择器对应的分页组件，不执行返回页面的 JavaScript。已有静态下一页链接仍优先使用；参数无法解析或页码、筛选条件不一致时显示错误。其他动态分页格式仍需适配。

升级后刷新原网页，原有选择器规则无需重建；已显示“已结束”的旧页面需要刷新才能使用修复。

## 网站重绘导致追加内容消失

v1.8.1 增加每条规则独立的 **兼容网站重绘（保护追加内容）** 开关，位于 **加载设置**，默认关闭。遇到“下一页出现后马上消失”时，可以为该网站勾选并保存，然后刷新页面。已有追加内容时，改变此模式需要刷新。

v1.8.2 调整首次翻页时机：开启重绘兼容后，等待网页 `load` 完成，且列表连续 **800ms** 没有结构或文字变化，再建立列表基准并开始翻页。等待中发生变化会重新计时；整个容器被替换时等待新容器稳定。当前页的后台打开和三天标记也在初次稳定后应用，减少接管网站首轮渲染的干扰。

首次等待最多 **10 秒**，持续变化或未完成加载时停止并提示刷新，不强行追加。手动点击加载也会排队等待，重复点击不会重复请求；暂停、删除或切换页面可取消加载。首次等待使用临时的列表子树监听，完成后释放并切换回直接子节点监听；后续翻页不会重复等待 800ms，不新增轮询定时器。

通用脚本无法读取所有网站的内部“渲染完成”信号，这里的稳定检测是一种判断方式。首轮重绘发生于等待期间时，下一页直接追加一次；超过静默窗口后才发生的重绘仍使用下面的恢复机制，不能保证所有网站永远只插入一次。

- 内容容器被清空、部分追加条目被删除或整个容器被替换后，核对首屏内容签名与条目顺序，再恢复保留中的追加节点。保留累计页数与下一页进度，恢复本身不请求页面。
- 同一容器监听直接子节点的增删，不监听属性或整个子树；容器整体替换通过已有的网址检查发现，不新增轮询定时器。恢复任务合并等待 150ms，首屏暂时为空或容器暂时缺失时最多检查 10 次。
- 30 秒内最多恢复三次，反复清除时停止并显示原因。检测到筛选内容变化、多个候选容器或追加节点被移动到其他位置时也停止，避免混入旧内容或重复追加。
- 支持内容容器的直接子条目；嵌套条目需要调整选择器。容器重建后重新绑定后台打开及三天标记功能；暂停与末页状态保持原样。
- 脚本自身回收旧页不会触发恢复，回收后释放保护缓存中的旧节点。只恢复尚未回收的追加内容，不缓存旧 HTML；已回收旧页后整个容器被重建时停止，需刷新页面。
- 停用、删除、导入规则或切换页面时取消待执行恢复并断开监听。恢复失败会释放已脱离 DOM 的页面和链接引用。

这是针对网站重绘的通用兼容选项，已经用本地模拟页面验证，未验证反馈问题的实际网站。它不保证解决网站自身的 Svelte hydration 警告，也不将接口分页或虚拟列表变为支持的分页形式。若开启后仍消失，可查看面板中的停止原因。

## 最近三天打开记录

v1.8.0 新增独立的 **标记最近三天打开过的链接** 开关，默认关闭。在对应网站的规则中勾选并保存，开启后会将已打开的条目网页链接文字变灰。可与后台打开同时使用，也可单独记录普通点击。

- 按最近一次打开时间保留 **72 小时**，再次打开重新计时。关闭页面或重启浏览器后，重新访问同一网站仍会恢复未过期的标记。
- 当前页和追加条目使用相同记录，同一地址的链接统一标记；同一网站的其他脚本标签页同步更新。
- 地址使用 HTTP / HTTPS 链接，忽略 `#` 片段，保留查询参数。不同协议、域名或端口的网站分别保存记录。
- 从启用功能后的打开动作开始记录，不读取或补回浏览器历史。标记代表触发过打开，不表示页面已经读完或加载成功。
- 锚点、下载、分页、磁力链接、被取消的原生点击和可视化点选不记录。浏览器右键菜单和网站自行执行的其他跳转不保证被记录。
- 活跃页面使用一个到期任务撤销过期的脚本标记；重新访问网站时清理过期记录。设备关闭或没有该网站标签页时，物理清理在下次访问时完成。
- 关闭标记开关、停用或删除规则会恢复网站原样式并清理监听，三天内的记录仍可在重新启用时使用。网站自身的 `:visited` 颜色独立于脚本标记。

记录只保存在使用设备的 Tampermonkey 用户脚本存储中，不上传到 GitHub 或任何服务器，不自动跨设备同步，规则 JSON 导出也不包含打开历史。追加页面只处理新增链接，记录变化只更新对应地址的链接；回收旧页会释放标记缓存中的节点。

## Page Down 按整排卡片滚动

v1.6.0 新增每条规则独立的 **Page Down 按整排卡片滚动** 开关，默认关闭。在对应网站打开配置、勾选并保存即可立即生效。

- 底部有未完整显示的一排时，将这一排顶部对齐可阅读区域顶部。
- 底部恰好完整显示一排时，从下一排开始。按实际卡片位置计算，不固定三排或四列。
- 支持等高卡片网格，以及普通纵向条目；窗口大小、列数变化后重新计算。超高条目分段前进，并保留阅读重叠。
- v1.7.0 默认使用 **自动识别顶部遮挡**：在按键时采样内容区域顶部的可见固定栏和吸顶栏，多层遮挡按并集计算；跳转后同步复核 CSS 吸顶状态。
- 可在“加载设置 → Page Down 顶部避让”选择 **手动指定高度**，填写 **Page Down 顶部预留高度（px）**。手动值完全覆盖自动识别，`0` 表示不预留。
- 旧规则非零预留高度保留为手动模式；旧默认零值使用自动模式。自动检测不依赖 `.navbar` 类名，也不扫描全站所有节点。
- 输入框、可编辑区域、设置面板、其他滚动区域、组合键和 Page Up 保留原行为。
- 支持页面及内容容器内部滚动，受浏览器可滚动范围限制；末尾不能强制留出额外空白来对齐。

只在按下普通 Page Down 时读取当前位置并检测顶部遮挡，不增加持续滚动检测或定时器。自动检测针对覆盖内容区域至少一半宽度的顶部栏；细小浮动按钮、侧栏、跨 iframe / Shadow DOM 的特殊结构、带延迟的 JavaScript 导航动画可能需要手动指定高度。暂停自动加载后仍可使用整排阅读；关闭该开关、停用或删除规则会移除按键监听。规则导入导出包含此开关与顶部预留高度。

## 回收旧页，不恢复内容

在对应规则的 **加载设置** 中开启 **回收离开视口的旧页（不恢复）**，默认保留目标为 **10 页**。旧规则默认关闭，需要为使用的网站单独开启。

超过目标后，回收已经完全离开视口的旧页，并清理脚本保存的节点、链接属性缓存和去重键。只使用一个累计高度占位保持滚动空间，不缓存旧 HTML 或节点。向上滚动不会恢复旧内容。

- 累计加载上限与保留页数独立；状态中分别显示累计、保留和回收数量。
- 当前阅读内容优先保留，可能暂时超过保留目标；滚出视口后再回收。
- 支持直接子条目、列表、表格及可安全补偿的自动 Grid。Grid 按完整行组回收，可能保留少于设定的页数。
- 嵌套、分栏、自定义组件或无法安全补偿的布局会暂停回收，并显示原因。补偿失败会还原节点。
- 修改回收模式需要刷新当前页面；修改保留页数可以立即应用。被移除内容只有重新访问原页面才能查看。
- 回收模式的条目去重覆盖保留内容，分页循环检测仍覆盖所有已访问页面。

## 性能

- 未配置的网站只读取一次规则，不创建配置界面，也不启动网址轮询或翻页观察器。
- 配置界面首次打开时才创建，之后复用，关闭或进入点选模式时停止更新状态；重新显示时同步最新状态，相同值不重复写入。
- 旧页回收检测按 200ms 间隔节流，滚动停止后仍执行最后一次检查；没有待处理任务时不保留回收定时器，删除前仍检查实际位置。
- 当前域名存在启用规则时才监听网址变化，匹配结果使用缓存。
- 追加页面只处理新增条目的链接，减少重复扫描和属性写入。后台打开只为内容容器绑定一个点击监听，不逐条绑定；关闭开关、停用或删除规则时移除。
- 点选与高亮按动画帧合并更新，同一目标复用选择器。
- 已识别的页内锚点切换会保留翻页进度和在途请求。
- 重绘兼容仅为单独勾选的规则启用；未启用时不创建内容 MutationObserver 或保护节点缓存。初次稳定后，图片加载和无关节点移除不触发条目扫描或布局读取。首次等待期间只在列表结构或文字变化时重新安排一次任务，最长等待 10 秒。

168 项本地浏览器检查通过。新增 13 项验证首次静默窗口、渲染重新计时、加载完成信号、首屏替换、延迟出现的分页链接、暂停、超时与清理，以及只等待首次翻页；另有 27 项验证重绘恢复、容器替换、有限重试、频繁重绘停止、筛选和重复内容保护、在途请求、自动继续、监听清理，以及与后台打开、三天标记和旧页回收的组合。原有 128 项检查仍覆盖跨天恢复与过期、导航避让、整排键盘滚动、动态分页、链接处理、性能调度、回收位置稳定及规则兼容。在相同的 12 页、每页 100 条测试中，条目链接扫描次数从 v1.3.0 的 7800 次减少为 v1.4.0 的 1200 次。这是该测试场景的操作次数，整体耗时仍取决于网站、图片和网络。

v1.5.1 的可控时钟测试中，首次检查后模拟 1 秒内 100 次滚动，只追加 5 次回收检测；旧页仍可见时的重复状态没有产生 DOM 写入。这些结果验证调度与写入次数，不代表实际网站的 CPU、内存或帧率提升比例。

## 数据与支持范围

各网站的规则保存在使用设备的 Tampermonkey 用户脚本存储中。仓库只提供通用代码和说明，不收集或上传规则、打开记录或页面内容。开启三天标记功能后，打开地址与时间仅保存在本机用户脚本存储中。

适合各页结构一致、下一页返回完整 HTML 的同源分页。支持常见图片懒加载、相对链接、`srcset`、UTF-8 / GBK 等声明编码，以及整页或容器滚动。

JSON 接口、必须执行页面脚本才有内容的页面、虚拟列表、POST 分页、iframe 或 Shadow DOM 内容，需要专门适配。依赖页面初始化脚本的交互不保证恢复。尚未在所有真实网站或真实 Tampermonkey 环境中完成验证。后台打开测试使用模拟接口验证 `active: false` 和阻止当前页跳转，未在用户另一台设备上实测标签页焦点。

## 维护发布

每次发布时同时递增完整脚本与元数据文件的 `@version`。`visual-autopager.meta.js` 应为完整脚本开头的 UserScript 元数据块，不包含运行代码。两个固定 Raw 地址保持不变。

个人规则导出的 JSON 不应提交到本仓库。问题反馈可使用 [Issues](https://github.com/1789984734/visual-autopager/issues)。
